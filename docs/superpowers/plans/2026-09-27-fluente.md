# Fluente Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Web app que mede a fluência leitora (palavras corretas por minuto) a partir de 60 s de leitura em voz alta, transcrita pela AssemblyAI e alinhada deterministicamente ao texto.

**Architecture:** Next.js 16 App Router. O navegador grava 60 s (`MediaRecorder`) e envia o áudio para `POST /api/leituras`; o servidor manda para a AssemblyAI (upload + transcript + polling), alinha a transcrição ao texto com uma função pura, grava o resultado no Postgres (sem áudio) e devolve. O navegador guarda o áudio localmente para tocar trechos.

**Tech Stack:** Next.js 16, React 19, Tailwind 4, Vitest, `postgres`, `zod`, AssemblyAI pre-recorded API, Vercel.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-09-27-fluente-design.md` (ler inteiro).
- Código simples, **sem comentários**. Inglês padrão; `?lang=pt` para português; todo texto de interface num dicionário `lib/i18n.ts`.
- AssemblyAI: `speech_models: ["universal-3-5-pro"]`, `language_code` do idioma, `disfluencies: true`, **nunca** `keyterms_prompt`/`prompt` com o texto. Header `authorization: <ASSEMBLYAI_API_KEY>` (sem Bearer). Chave só no servidor.
- Áudio nunca é salvo no servidor nem no banco.
- `/estudo` exclui `lower(apelido) = 'teste'` e nunca mostra apelido.
- `.env.local` (copiar de `~/dev/sinal-de-alarme/.env.local` as chaves `ASSEMBLYAI_API_KEY`, `DATABASE_URL`, `IP_SALT`; nunca imprimir segredos). Build local: `NEXT_TELEMETRY_DISABLED=1`.

- [ ] `lib/alinhar.ts` (TDD, função pura):

```ts
export interface PalavraLida { texto: string; inicio: number; fim: number }
export type Marca = "correta" | "trocada" | "pulada" | "autocorrecao" | "nao_lida"
export interface ItemTexto { indice: number; esperada: string; marca: Marca; dito?: string; inicio?: number; fim?: number; hesitacao?: boolean }
export interface Extra { texto: string; inicio: number; fim: number; tipo: "repeticao" | "insercao" }
export interface Resultado { itens: ItemTexto[]; extras: Extra[]; corretas: number; erros: number; lidas: number; segundos: number; pcpm: number }
export function normalizar(p: string): string
export function tokenizar(corpo: string): string[]
export function alinhar(corpo: string, palavras: PalavraLida[], idioma: "pt" | "en"): Resultado
```

Regras (spec §3): hesitações removidas (`é, e (quando sozinho entre pausas não — só "é"), hã, ahn, hum, hm, um, uh, er, ah, eh`) — use a lista `é hã ahn hum hm eh ah` para pt e `um uh er ah hmm eh` para en; só palavras com `inicio < 60000`; DP de edição mínima (custo 1 para substituição/inserção/remoção) com **fim livre**: o alinhamento pode terminar em qualquer posição do texto, e as palavras do texto depois da última alinhada ficam `nao_lida` (não contam como erro). `pulada` só para palavras do texto antes da última alinhada. Inserção igual à palavra esperada anterior ou seguinte → `repeticao`; `trocada` imediatamente seguida de inserção igual à esperada → o item vira `autocorrecao` e a inserção some. `hesitacao: true` se a pausa entre o fim da palavra lida anterior (ou 0) e o início desta passar de 3000 ms. `corretas` = correta + autocorrecao; `erros` = trocada + pulada; `lidas` = corretas + erros; `segundos` = min(60, fim da última palavra lida em s), mínimo 1; `pcpm` = round(corretas × 60 / segundos).

Testes obrigatórios (todos com números exatos): leitura perfeita do texto inteiro em 30 s → pcpm = palavras×2; para no meio (texto de 10, lê 6 certas em 20 s) → 4 `nao_lida`, corretas 6, erros 0, pcpm 18; uma trocada (guarda `dito`); uma pulada no meio; repetição (lê "o menino menino correu") não é erro; autocorreção ("casa... caça" onde o texto diz "caça") conta correta; hesitação "é" removida e pausa de 3,5 s marca `hesitacao`; palavras após 60000 ms ignoradas; acentos/pontuação/maiúsculas ("Pássaro," == "passaro"); transcrição vazia → corretas 0, pcpm 0, todos `nao_lida`.

### Task 2: Transcrição, banco e API

**Files:** `lib/db.ts`, `lib/ip.ts`, `lib/transcrever.ts`, `db/schema.sql`, `scripts/migrar.mjs`, `app/api/leituras/route.ts`, `app/api/leituras/[id]/route.ts`, `app/api/leituras/[id]/contagem/route.ts`, `.env.example`.

- [ ] `db/schema.sql`: tabela `leituras` do spec §4 (`create table if not exists`), índices por `criada_em` e `ip_hash`. `npm run migrar`.
- [ ] `lib/transcrever.ts`: `transcrever(audio: ArrayBuffer, idioma): Promise<PalavraLida[]>` — upload bruto (`POST https://api.assemblyai.com/v2/upload`, corpo binário), cria transcript com as opções dos Global Constraints, polling a cada 700 ms até `completed`/`error` (timeout 60 s), devolve `words` mapeadas para `{texto, inicio, fim}`. - [ ] `GET /api/leituras/:id` devolve a leitura (sem ip_hash).
- [ ] `POST /api/leituras/:id/contagem` `{ contagem: 0..400 }` grava `contagem_manual` (pode sobrescrever).
- [ ] Verificação real: gerar um áudio de teste lendo um texto (ex.: TTS local do Windows via PowerShell `System.Speech` salvando WAV, ou qualquer WAV com fala) e mandar para a API em `next start -p 3040`; conferir pcpm plausível; apagar leituras `teste`. Commit `transcrição, banco e api`.
